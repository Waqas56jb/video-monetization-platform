Section 01

Design Approach & System Scope

The system is deliberately kept simple, fast to implement, and easy to use on site. It is one interconnected system — not a collection of forms — where time, progress, cost and payment are driven by the same data.

Four Governing Principles

PrincipleWhat it means in practice
One data backboneEvery record belongs to Project → Package → Subcontract → BOQ Item. Data is entered once and reused by every module and the dashboard.
Quantity-based progressProgress is never a typed-in estimate. It is calculated from executed quantities against BOQ values, so Actual % always equals earned value ÷ contract value.
Pay only certified workPayment certificates are generated from verified, certified quantities — not from the subcontractor's claimed percentage.
CPMS controls the project, ERP controls the moneyThe CPMS manages progress, certification and cost control. Approved certificates are passed to the ERP, which remains the only accounting system.

Core Scope — Phase 1

Kept out of Phase 1 by design: engineering registers (RFI/submittals/NCR), testing & commissioning, cost-plus billing, and advanced reporting. The data backbone is structured so these can be added later as plug-in modules without rework.

Section 04 · Modules M1 – M2

Subcontracts, BOQ & Quantity-Based Progress

M1 — Subcontracts & BOQ

Each subcontract (Architectural, Electrical, Mechanical, HVAC, Gas, Elevators, …) is registered with its contract value, dates, advance and retention terms, and its full BOQ imported from Excel. The BOQ becomes the measuring stick for everything that follows — every item's value is its weight in the progress calculation.

M2 — Progress Control

Actual % = Σ ( Executed Qty × BOQ Rate ) ÷ Contract Value
Planned % = from activity start/finish dates, weighted by BOQ value
Delay = Planned % − Actual %  (per subcontractor, package and project)
  • Site engineers enter only executed quantities per BOQ item (weekly or per claim) — the system computes every percentage. No estimated % is ever typed in.
  • Certified % is a third, separate figure that moves only through the M3 verification workflow.
  • Planned vs Actual S-curve and delay table are generated automatically at all levels.

Section 05 · Modules M3 – M4

Certification, Payments & Variations

M3 — Payment Certification Workflow

Rule of the system: if a subcontractor claims 60% but site verification supports 45%, the certificate is generated from the verified quantities only. The claim stays on record for reference — money always follows certified work per the contract and BOQ.

Automatic Certificate Calculation

  Value of work completed to date (certified quantities × BOQ rates)
− Previously certified amount
+ Approved variations (this period)
− Retention (per contract %)
− Advance recovery (per contract schedule)
− Back charges / deductions
= NET AMOUNT DUE → exported to ERP payable

Retention and advance balances are tracked automatically per subcontract across the full contract life.

M4 — Variations (Two Registers, One Link)

  • Subcontractor VOs — value, status (pending / approved / rejected), effect on subcontract value and certificates.
  • Client VOs — value, approval status, billing status toward the client.
  • Each subcontractor VO carries a client-recovery flag, so the system always shows the exposure: cost approved to a subcontractor but not yet recovered from the client.
  • Approved VOs flow automatically into cost control and the expected final cost.

Section 06 · Modules M5 – M6

Procurement, Materials & Cost Control

M5 — Procurement & Material Status

  • Purchase orders registered against project / package with supplier, value and delivery terms.
  • Every PO line carries a required-on-site date and an expected vs actual delivery date.
  • Material status at a glance: Ordered → Approved → In transit → Delivered.
  • Any expected delivery later than its required-on-site date is flagged automatically as a procurement-driven delay and surfaces on the dashboard against the programme.
  • PO values feed committed cost in M6 the moment they are approved.

The question this module answers: not "how much have we paid?" but "what will this project finally cost?" — visible at any moment, for any package, without waiting for month-end accounts.

Cash Position View

Because certified, paid and balance figures are live per subcontract, the project cash exposure — work certified but not yet paid, and advances not yet recovered — is always one click away for management.

Section 08

ERP Integration & Next Steps

Deliberately Simple Integration

The CPMS never becomes an accounting system. It exchanges only what the ERP needs, against synchronized master codes, so nothing is entered twice.

Built Simple, Ready to Grow

The backbone is structured so later modules — engineering registers, testing & commissioning, cost-plus billing, client certification — plug into the same hierarchy without rebuilding what Phase 1 delivers.

Proposed Path Forward

StepAction
01Architecture approval — your review and sign-off of this document (Rev A).
02Data preparation — BOQ formats, subcontract list, cost codes and ERP reference codes agreed.
03Module-by-module build — in the order M1 → M2 → M3 → M6 → M4 → M5 → M7, each reviewed with you before the next begins.
04ERP link & go-live — certificate export tested against the ERP, dashboard live with real project data.

Summary. A simple, quantity-driven system where every payment follows certified work, every cost rolls up to a live forecast final cost, and one dashboard shows the true position of every subcontractor and the project — with the ERP untouched as the financial system of record.
